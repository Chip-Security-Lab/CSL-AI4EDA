# FSM with a Functional Correction

This case was generated by CSL_HDLGen 0.3.13 using DeepSeek `deepseek-flash` on November 1, 2026. It includes two real-model Verilog-2005 outputs and their recorded compilation and finite simulation results.

The normal cycle is `IDLE → RUN → DONE → IDLE`. An additional `MAINT` state has no incoming transition, so it cannot be reached from reset.

| File | Behavior |
| --- | --- |
| `original.v` | Keeps the declared MAINT state and its transition to RUN, while applying the common coding safeguards. |
| `repaired.v` | Removes the unused MAINT state under the requirement's explicitly allowed repair assumption. Its former encoding, `3'b011`, follows illegal-state recovery to IDLE. |

Both files use the same module name, `live_functional_fsm`, and the same ports. Their normal cycle and timing are unchanged. Removing MAINT is a proposed functional change that requires agreement with the design intent.

## Files

- `requirement.txt`: the original design request and allowed correction.
- `original.v`, `repaired.v`, `variants.diff`: the two implementations and their differences.
- `security-report.txt`, `knowledge.txt`: the original report and supporting references; references may also have been used to rule out candidate issues.
- `tb.v`, `verification.json`: the independent testbench and recorded results.
- `original.compile.log`, `original.simulation.log`, `repaired.compile.log`, `repaired.simulation.log`: the tool logs for each version.

The report describes proposed measures. The external checks recorded in `verification.json` cover normal cycles, outputs, reset, illegal encodings and the different behavior of encoding `011`; they do not prove complete security.

The original report uses export labels `name.v` and `name_repaired.v`; these correspond to the saved `original.v` and `repaired.v` files respectively.

## Generate with the plugin

Configure your model, select **Secure FSM**, paste `requirement.txt`, turn off **Demo template**, and click **Generate**. Use the version selector to compare the outputs. New model responses may differ from these saved files.

## Run the saved code

Install Icarus Verilog with `iverilog` and `vvp` on your PATH. From this folder, compile each version separately because both define the same module:

```sh
iverilog -g2005 -s tb -Ptb.EXPECT_REPAIRED=0 -o original.vvp original.v tb.v
vvp original.vvp
iverilog -g2005 -s tb -Ptb.EXPECT_REPAIRED=1 -o repaired.vvp repaired.v tb.v
vvp repaired.vvp
```

Successful runs print `PASS FUNCTIONAL FSM ORIGINAL:` and `PASS FUNCTIONAL FSM REPAIRED:` with no `FAIL` message. No model account or Neo4j service is needed to run these saved files.
